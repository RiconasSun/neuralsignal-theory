# Content and transport closure contract

The frozen247 owner/closure rows retain their original IDs and text. `REQUIREMENT_TRACE.json` maps each individually to evidence; `SEMANTIC_ACCEPTANCE.json` supplies explicit test oracles for the material conditions. Conditional outcome-A-only proposal requirements are verified as **condition not met, no proposal or activation**, preserving the original rule. They are not converted to an unconditional deliverable or dropped to obtain PASS.

Before closure, review and future Git/terminal rows remain OPEN. No tracked file can truthfully contain its own future Git commit hash. The final independent review must name the exact diagnostic manifest hash, unchanged inspected hashes, review/defect outcome and independently verified saved reproduction. It may approve archive content only. It cannot replace actual transport proof.

Final independent review files and post-freeze saved-reproduction logs are closure evidence outside the payload manifest. The manifest itself and `work/` are also excluded. `payload_contract.py` independently fixes the exact nonempty expected payload filename set; reproduction verifies that set and every SHA256/byte size. The daily prefix is excluded from the payload but must preserve the byte-exact BASE suffix and be reviewed before staging.

After content acceptance, perform fresh fetch, confirm origin/test has not advanced and origin/main remains absent (or reclassify without inventing a ref); stage only exact P/E mission files and the reviewed daily prefix; inspect the staged set/diff/deletions; byte-compare the staged blobs to the reviewed local files; normal commit and normal push only to origin/test. Do not start a PR, alter main or use reset/clean/force/broad staging.

Then fetch and read `ls-remote` to verify the actual commit. Read **every changed origin/test blob**, compare exact bytes/Git blob ID/SHA256 to the committed/local payload, check unchanged BASE tracked files other than the daily prefix, verify no deletions and clean working tree. Preserve reviewed manifest and review hashes. Write actual `work/closure_receipt.json` with complete changed-file manifest, readback identities, counts, fresh timestamps and all247 terminal requirement rows. Review/transport rows become VERIFIED only by those executed predicates, not pre-filled assertions. If any predicate fails, remain in execution/repair; do not claim archive PASS.

The ignored receipt is local execution evidence for the exact pushed tree; it is not a substitute for tracked diagnostic evidence or independent review. The final user response supplies the actual commit and remote result. This distinction avoids recursive commit-hash claims. Scientific disposition B and zero-activity boundaries are identical before and after archive closure.
