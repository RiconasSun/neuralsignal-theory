# Saved-only host recovery trust boundary

The current Windows custodian is trusted to administer local host storage. The fresh recovery process is a constrained saved-model verifier, not an analysis worker or release principal. This mission does not claim malicious administrator resistance. The original AppContainer controller/ledger and its historical actual-principal tests remain authoritative for release control; no new release authorization is created and the controller is never invoked.

All original92 source identities are verified (the permitted release_control dependency amendment is compared against archived original bytes). New host sources are frozen and independently reviewed. Selection has a literal original version/hash and a fixed path. The source verifier rejects any non-dependency controller change. Source snapshots and reviews are local trusted-custodian attestations, not remote attestation or signatures against a hostile custodian.

Before real saved access, both independent reviews must hash-bind the frozen snapshot and passing synthetic evidence. A single public attempt record is durably created first. A distinct protected directory is consumed by atomic mkdir; files use exclusive creation/fsync. ACLs deny AppContainers and permit custodian/SYSTEM only, including protected non-inherited DACL verification. Old partial storage is only read and never chmod, replaced or deleted. Duplicate or concurrent requests lose at directory creation; interrupted namespaces remain poisoned. No automatic retry or rollback exists.

A Python audit hook denies raw C_only/D_only input paths, neural sources, encrypted sources/keys, checkpoint/input arrays, all model-array paths except the saved complete_states.npz, ledger opens, subprocesses, network and fitting imports. It records every audited open. This guard constrains the reviewed host code, not arbitrary malicious native extensions or a machine administrator. Native numpy/crypto/ACL libraries are preloaded; no untrusted extensions are authorized. Existing runtime hashes are preserved in provenance. Current host/runtime versions are reported separately.

Synthetic tests use genuine historical saved fixtures and conspicuously labelled synthetic prospective metadata. They test fresh processes, hash/import denial, saved-state corruption, namespace reuse/concurrency/interruption and forbidden C/D/key/source/ledger/import canaries. They do not access real C/D raw arrays, keys or D files. Historical 26 actual D CreateFile denials are retained as prior evidence, not falsely described as fresh D accesses. Original release controller/signature/ledger bytes outside the dependency import are identical; saved-only code has no consume/grant/key path. Injected failures never count as releases.

The exactly-once D ledger remains outside this process and cannot be opened by its audit policy. No D entitlement exists for this mission, so there is nothing to consume, restore or regenerate. D_RELEASE_CONSUMED and D_EVALUATION_EXECUTED must remain false. Saved-state integrity, not any new scientific validation, is the result.
